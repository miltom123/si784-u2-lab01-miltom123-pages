Automatizaciones y distribución

Documentación y cobertura en un mismo sitio

publish_docs.yml se ejecuta con cambios en la biblioteca, documentación, herramientas y scripts. publish_cov_report.yml se ejecuta con cambios en las pruebas, y en solicitudes de incorporación a main. Ambos admiten ejecución manual.

Ambos llaman a publish_site.yml, que restaura dependencias, compila, ejecuta MSTest con Coverlet, valida la cobertura, genera DocFX y ReportGenerator y guarda evidencias como artefactos. En main publica un único sitio con la documentación en la raíz y la cobertura en cobertura/. Cada publicación genera el sitio completo: ninguno de los dos reportes elimina al otro. Una concurrencia común serializa las publicaciones. En solicitudes de incorporación solo se construye y verifica.

El despliegue requiere que un administrador active Settings → Pages → Build and deployment → Source → GitHub Actions. GITHUB_TOKEN necesita pages: write e id-token: write; no se almacenan credenciales personales en el código. Si Pages no está habilitado, los artefactos se generan antes del paso de despliegue y se pueden descargar desde Actions.

Paquete y release

release.yml se ejecuta al subir una etiqueta v2023078333.0.N, por ejemplo v2023078333.0.0. Valida que coincida con la versión declarada en el proyecto, compila, ejecuta las pruebas y empaqueta UPT.EPIS.MyMath.2023078333. Publica en el registro NuGet de la organización y crea un release con el .nupkg.

La matrícula 2023078333 es el componente principal de la versión NuGet 2023078333.0.0. La versión del ensamblado y del archivo se mantiene en 1.0.0.0 porque sus componentes tienen un límite de 65534, que la matrícula supera. Para una nueva entrega se incrementa el último componente tanto en el proyecto como en la etiqueta. Una versión ya publicada no se sobrescribe.

dotnet pack MyMath/Math.Lib/Math.Lib.csproj -c Release -o artifacts/packages
git tag v2023078333.0.0
git push origin v2023078333.0.0

El flujo utiliza packages: write, contents: write y el token temporal de Actions. La organización debe permitir crear paquetes. La visibilidad inicial y el acceso del paquete dependen de las políticas de GitHub Packages y del repositorio.

Instalación desde GitHub Packages

Configurar el origen NuGet de la organización con una credencial personal que tenga read:packages, sin incorporarla al repositorio, y después ejecutar:

dotnet add package UPT.EPIS.MyMath.2023078333 --version 2023078333.0.0 --source https://nuget.pkg.github.com/UPT-FAING-EPIS/index.json
