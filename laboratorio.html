Desarrollo del laboratorio

1. Preparación y estructura

Se utiliza .NET 8, que satisface el requisito de .NET 6 o superior, y una solución con dos proyectos: Math.Lib, biblioteca de clases, y Math.Tests, pruebas MSTest. El segundo referencia al primero. Los archivos de ejemplo Class1.cs y UnitTest1.cs se sustituyen por Rooter.cs y RooterTests.cs.

dotnet new sln -o MyMath
dotnet new classlib -o MyMath/Math.Lib --framework net8.0
dotnet new mstest -o MyMath/Math.Tests --framework net8.0
dotnet sln MyMath/MyMath.sln add MyMath/Math.Lib/Math.Lib.csproj MyMath/Math.Tests/Math.Tests.csproj
dotnet add MyMath/Math.Tests/Math.Tests.csproj reference MyMath/Math.Lib/Math.Lib.csproj

No se necesita un contenedor para ejecutar este laboratorio: los pasos de la guía utilizan directamente el SDK de .NET. Tampoco requieren elevar privilegios.

3. Algoritmo de Newton

Para resolver x² - input = 0 se utiliza:

x(n+1) = (x(n) + input / x(n)) / 2

Se comienza en input si es mayor o igual a uno y en uno en caso contrario. La iteración termina cuando la diferencia absoluta entre aproximaciones consecutivas es menor o igual al 0,1 % de la aproximación actual.

La expresión de la guía result * result puede desbordarse con números grandes. Se usa su forma equivalente result / 2 + (input / result) / 2, que evita ese producto y evita sumar dos números grandes antes de dividirlos. La biblioteca implementa Newton sin llamar a System.Math.Sqrt; esta última se usa únicamente como referencia independiente en las pruebas adicionales.

4. Dominio y excepción solicitada

El contrato es número finito estrictamente positivo. Se rechaza cero conforme a la condición input <= 0.0 del paso 17. También se rechazan NaN e infinitos para que no se acepten entradas sin una raíz real finita.

Se produce ArgumentOutOfRangeException con ParamName = "input", el valor recibido y el mensaje literal:

El valor ingresado es invalido, solo se puede ingresar números positivos

.NET agrega información del parámetro y del valor al mensaje de la excepción. Por ello, la prueba valida que el texto empiece por el mensaje solicitado y comprueba por separado ParamName y ActualValue.

6. Cobertura y documentación

Coverlet registra las líneas y ramas ejecutadas de Math.Lib en Cobertura XML. ReportGenerator transforma ese archivo en HTML. El script exige 100 % de líneas y ramas en esta biblioteca pequeña; un valor menor detiene la publicación. La cobertura por sí sola no garantiza corrección: se complementa con aserciones de precisión, excepciones y límites numéricos.

Los comentarios XML documentan clases, constantes, métodos, parámetros, retorno, excepciones y ejemplos. GenerateDocumentationFile genera el XML de la biblioteca y TreatWarningsAsErrors impide dejar miembros públicos sin documentar. DocFX genera la referencia navegable a partir del proyecto y esos comentarios.

7. Conclusiones

La prueba básica aislada no detecta el defecto de dividir entre dos. El rango ampliado demuestra la necesidad de refinar el algoritmo. Las pruebas de dominio definen cómo debe responder la biblioteca ante entradas inválidas. La automatización repite las comprobaciones antes de generar documentación, cobertura y el componente.
